Low-power wireless sensor node

An ESP32 sensor node that went from about 3 days to 6 weeks on one 18650 cell by sleeping between readings.

2026. ESP32, C, I2C and KiCad.

Sleep between reads

The node reads a sensor over I2C once a minute and sends the reading. An ESP32 draws far more current awake than asleep, so the firmware keeps it awake as briefly as possible. It sleeps, wakes every 60 seconds, takes one reading, sends it and goes back to sleep.

The first version lasted about 3 days on one 18650 cell. With this schedule it lasted 6 weeks, which is 42 days and 14 times as long.

Why sleeping saves so much

Battery life depends on the average current, not the peak. A node that is awake for a moment each minute has an average close to its sleep current, because the time at the high current is so short. Reading the sensor, waiting for it and sending the reading all happen while the chip is on, so the code keeps that window short.

The board and the missing pull-up

One 18650 cell powers a 2-layer board that I drew in KiCad. On the board an ESP32 runs the C firmware and talks to the sensor over I2C, a two-wire bus.

I2C lines are only pulled low by the chips on the bus. A resistor, called a pull-up, has to bring them back high. One was missing on this board, and I found it with an oscilloscope. A scope shows the line itself, which a debugger on the firmware cannot.
