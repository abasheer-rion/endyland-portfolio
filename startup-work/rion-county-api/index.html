County records API and client intake

One API in front of 3 county record systems, and client intake that runs on its own.

Three county systems and a lot of typing.

Property, owner and records information each live in their own county system. Anyone who needed a full picture had to ask three places and put the answers together by hand.

Client intake had the same shape: the same details typed into more than one place, which is where duplicate entries come from.

One API in front, a cache behind it, intake on autopilot.

I put all 3 county systems behind one API, so a caller asks one place, not three. The API caches answers, so a repeat lookup does not hit the county system again. It handles 1K+ lookups a day.

I also automated client intake end to end. A client is entered once and the rest runs on its own. Onboarding got 70% faster and duplicate entries stopped.

What I learned

One clean interface hides messy systems. Callers never needed to know there were three of them.

A cache is the cheapest speed-up when the same questions repeat.
