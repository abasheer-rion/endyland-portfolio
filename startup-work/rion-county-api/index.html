County records API and client intake

One cached API in front of three county record systems, and client intake that runs from a single entry.

Automation engineer, September 2025 to June 2026. Python, Flask and AWS Lambda.

Lookups

Property, owner and records information each live in their own county system. A full picture used to mean asking three places and combining the answers by hand. The API reads all three, caches answers so a repeat lookup does not call a county system again, and handles 1K+ lookups a day.

Client intake

Client intake meant typing the same details into more than one system, which produced duplicate entries. Intake now runs from one entry. Onboarding got 70% faster and duplicates stopped.
