Voice network device backups

200+ live voice-network devices had no backups. I automated the fix.

Role
Found the gap and automated the fix
Dates
Verizon internship, 2025 and 2026
Stack
  • Python
  • SSH
  • Internal tool. No public link.

The problem

Live voice-network devices, session border controllers among them, were set to keep no backups. That left disaster recovery open on a live carrier voice network: if a device failed, there was nothing recent to restore from.

I found 200+ devices in that state, and set out to close the gap.

What I built

I wrote Python automation that takes the backups over SSH and the devices’ own command line, so they run on their own.

I tested it unattended for 3+ days on 4 nodes and checked that a restore worked from the backups, end to end. While configuring the devices I found a firmware dependency, which meant the planned rollout was not supported. I stopped it before it went out.

Last, I wrote a requirements spec of 25+ items and handed the work to operations.

What I learned

  • Test the restore, not just the copy. A backup you have never restored is a guess.
  • A good gate saves more than it costs. Finding the firmware dependency before the rollout was cheaper than finding it after.
  • Hand over with a spec. Writing down what the backups must do is what let someone else run them.
