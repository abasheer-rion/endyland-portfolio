Two summers, three problems

I was a network engineer intern on the software and automation side, in Richardson, TX, in the summers of 2025 and 2026. The work was the kind people do by hand until someone writes it down as code: setting up carrier trunks, keeping backups of voice-network devices, and moving applications from one platform to another.

I wrote the code in Python and Bash, worked over SSH and REST APIs, and wrote runbooks so the work could be handed on. Each project below has a clear result you can count.

Two smaller pieces sit beside them. My configuration scripts cut manual configuration time by 35%. Scripts I wrote for micro-node maintenance windows removed about 90% of the manual actions during firmware updates.

What I owned

  • Found 200+ live voice-network devices with no backups, and automated the fix.
  • Built the Carrier Trunk Provisioning Tool alone. It is the record system and API behind a $70M-a-year revenue line.
  • Built a release pipeline with 300+ automatic tests.
  • Moved apps off VMware to Verizon’s internal cloud, saving $480K a year, with $2M+ more projected.
  • Wrote a 25+ item requirements spec and handed the backup work to operations.

What I learned

  • Start with a count. The backup work began with a number of devices that had no backups, and that number made the case on its own.
  • Test the thing you will rely on. A 300-test gate is what let releases go out with no manual deploy steps.
  • Write it down for the next person. The 25+ item spec and the runbooks are what let operations own the work after I handed it over.
