The problem

A marketplace that already had sellers and shoppers, running on code nobody on the team had written.

YoTummy lets people buy homemade food from cooks and farmstands near them. When I joined I inherited the whole thing: a website, a seller portal, an admin panel and a phone app, all with real users. Payments sometimes failed to record, who could change what was not locked down, and there was no automatic deploy.

The founder also wanted the site to feel less like a directory and more like a place to browse. Both jobs landed on one developer, so the order of work mattered.

Approach

I fixed what could lose money or data first, then built what shoppers see, then pitched the bigger redesign with something they could click.

  1. Make it safe. Fix Stripe and App Store payments so a payment still records when a setup key is missing. Close the holes around who can change what.
  2. Make it ship. Set up automatic deploys, so a fix reaches users without a manual upload.
  3. Make it easier to find food. A map of nearby sellers that groups pins into bubbles and works on phones. New home page sections and polished in-app messaging.
  4. Show the next step. A separate Next.js prototype with a Mapbox photo-pin map and a category showcase, built to pitch a redesign to the founder.

How it works

Shoppers use the website or the phone app. Cooks use the seller portal to list food. The admin panel is how the owners run the marketplace. The older apps are Angular 12 and 18, and the phone app is Ionic and Capacitor, which is how one codebase reaches both stores.

The home page sorts food into 17 categories, from Baked Goods to Food Trucks, and the search box takes a ZIP code so results are local.

  • Built a separate Next.js prototype to pitch a redesign to the founder.

What I learned

  • With inherited code, fix payments and permissions before anything shoppers can see. Those are the failures people notice last and pay for most.
  • A map is mostly a performance problem. Grouping pins into bubbles is what keeps it usable on a phone.
  • A working prototype in the framework you would really use is a stronger pitch than a mock-up.
